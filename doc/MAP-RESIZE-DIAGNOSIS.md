# 지도 접힘 시 잘림 진단

## 결론

맛집 목록을 접을 때 바깥 레이아웃은 정상적으로 확장되지만, 이미 생성된 네이버 지도 인스턴스가 변경된 컨테이너 크기를 즉시 다시 계산하지 않는다. 그 결과 지도 타일이 이전 크기까지만 렌더링되고, 확장된 영역은 빈 공간처럼 남는다.

## 재현 결과

실행 중인 로컬 서버에 임시 Chrome으로 다음 상태를 재현했다.

| 환경 | 접기 전 지도 영역 | 접은 뒤 지도 영역 | 리사이즈 전 누락 영역 |
| --- | ---: | ---: | ---: |
| 데스크톱 1440×900 | 1022×900 | 1439×900 | 오른쪽 약 227px |
| 모바일 390×844 | 390×338 | 390×788 | 아래쪽 약 234px |

접힌 뒤 브라우저 `resize` 이벤트를 수동으로 발생시키면 두 환경의 누락 영역이 사라졌다.

## 코드 근거

- 데스크톱에서는 사이드바 폭이 `lg:w-[clamp(...)]`에서 `lg:w-0`으로 전환되고 지도 영역이 `lg:flex-1`로 확장된다.
- 모바일에서는 지도 높이가 `h-[40dvh]`에서 `h-[calc(100dvh-3.5rem)]`으로 전환된다.
- `react-naver-maps`의 `Container`는 지도 DOM을 `position: absolute`와 `width/height: 100%`로 배치하지만 크기 변경 감시를 제공하지 않는다.
- 네이버 지도 인스턴스는 한 번 생성된 뒤 컨테이너의 CSS 크기 변경을 앱에서 `autoResize()` 또는 `setSize()`로 통지하지 않는다.
- 현재 앱에는 지도 인스턴스 `ref`, `ResizeObserver`, 접힘 완료 후 리사이즈 호출이 없다.

따라서 원인은 Flex/Grid 자체의 폭 계산이 아니라 **레이아웃 전환 후 네이버 지도 viewport 리사이즈 호출 누락**이다.

## 수정 완료

`NaverMap` 내부에 `MapResizeObserver`를 추가했다.

- `useMap()`으로 현재 지도 인스턴스를 가져온다.
- `map.getElement()`를 `ResizeObserver`로 감시한다.
- 크기가 바뀌면 `requestAnimationFrame`에서 `map.autoResize()`를 호출한다.
- 연속되는 데스크톱 폭 transition 중 호출은 한 프레임 단위로 합친다.
- 지도 중심과 줌은 다시 설정하지 않아 접힘 과정에서 불필요한 위치 이동을 막는다.

수정 후 같은 조건에서 데스크톱과 모바일의 누락 영역이 모두 `0px`으로 확인됐다.
